## 0. 목표

- **만드는 것**: 낚시 다녀온 날의 조행 기록을 입력해서 저장하고, 목록과 상세로 다시 보는 웹앱. 혼자 쓴다.
- **진짜 목표**: 기능을 많이 만드는 게 아니라 **내가 만든 코드를 내 말로 설명할 수 있는 것.**

  - 매일 `NOTES.md`에 그날 만든 코드 하나를 자기 말로 3~5줄 적는다. (AI 설명 복붙 금지)

## 2. 저장할 항목 — 조행 기록 하나 (8칸)

| 항목 | 필드명 | 타입 | 필수 | 예 |
| --- | --- | --- | --- | --- |
| 날짜 | `date` | 글자(YYYY-MM-DD) | ✅ | 2026-09-28 |
| 장소 | `place` | 글자 | ✅ | 영종도 선착장 |
| 날씨 | `weather` | 글자(선택) | | 맑음 / 흐림 / 비 / 눈 |
| 어종 | `species` | 글자 | | 우럭 |
| 마릿수 | `count` | **숫자** | | 3 |
| 가장 큰 것(cm) | `maxSize` | **숫자** | | 28 |
| 상태 | `status` | 글자(선택) | ✅ | **성공 / 꽝** |
| 메모 | `memo` | 글자(여러 줄) | | 물때가 안 맞았다. 로드 A + PE0.8 |

- **`status`(성공/꽝)가 이 프로젝트의 "상태·분류"다.** 3단계 필터와 통계가 이 값을 쓴다.
- 장비·물때 같은 건 따로 칸을 만들지 않고 `memo`에 적는다. (칸이 많아지면 입력 화면 만드는 데 시간이 더 든다)
- 꽝인 날은 `species`를 비우고 `count`를 0으로 둔다.

### TypeScript 타입 (구현 때 `src/types/trip.ts`)

```ts
export type Trip = {
  _id?: string;
  date: string;      // YYYY-MM-DD
  place: string;
  weather: string;
  species: string;
  count: number;
  maxSize: number;
  status: '성공' | '꽝';
  memo: string;
  createdAt: Date;
};
```

## 3. 기능 — 3단계

### 1단계 — 반드시 (10/2까지)

| 기능 | 화면 | 내용 |
| --- | --- | --- |
| 등록 | `/trips/new` | 위 8칸을 입력해서 저장 → 저장되면 목록으로 이동 |
| 목록 | `/` | 저장한 기록이 카드로 쭉 보인다. 날짜 최신순. "+ 새 기록" 버튼 |
| 상세 | `/trips/[id]` | 카드를 누르면 8칸 전부 보인다. "< 목록" 링크 |

**1단계 완료 판정**: 브라우저에서 기록을 하나 넣고 → 목록에 뜨고 → 눌러서 상세가 보이면 끝.
추가로 새로고침해도 데이터가 남아 있어야 한다(MongoDB에 들어갔다는 뜻).

### 2단계 — 여기까지가 목표 (10/5~10/6)

| 기능 | 내용 |
| --- | --- |
| 수정 | `/trips/[id]/edit` — 저장한 기록을 고친다 |
| 삭제 | 지우기 전에 한 번 물어본다(확인창) |
| 검색 | 장소나 어종 글자로 찾는다 |

### 3단계 — 여유가 되면 (안 해도 됨)

| 기능 | 내용 |
| --- | --- |
| 필터 | 성공만 / 꽝만 보기 |
| 통계 | 총 출조 횟수, 총 마릿수, 성공률을 한 줄로 |
| 정렬 | 날짜순 / 마릿수순 전환 |
| 사진 | 기록에 사진 붙이기 (Vercel Blob, 안내 문서 부록) — **2단계 끝난 뒤에만** |
| 디자인 | Tailwind로 모양 다듬기 |

## 4. 하지 않는 것

- 외부에서 데이터 가져오기 (날씨 API, 물때 API 등) — **전부 손으로 입력한다**
- 로그인 / 회원가입 — 혼자 쓰는 앱이다
- 다른 사람과 공유, 알림 / 메일
- 배포 — 로컬 `npm run dev`로만 쓴다
- 사진 업로드 — 3단계로 미룬다 (1·2단계가 끝나기 전에는 손대지 않는다)
- 지도 / 달력 화면
- 자동 테스트

> 만들다 떠오르는 기능은 여기 아래에 메모만 해 둔다. 이번에는 만들지 않는다.

> - (메모 칸)

## 5. 데이터가 지나가는 길

발표 때 이걸 설명해야 한다.

```
저장 버튼을 누르면
1. trips/new/page.tsx   입력한 8칸 값을 모아서
2. fetch()              POST /api/trips 로 보내고
3. route.ts             받아서 MongoDB에 넣고
4. insertOne()          저장된 _id 를 돌려주고
5. trips/new/page.tsx   목록 화면(/)으로 이동한다
```

## 8. 작업하면서 지킬 것

- 하루에 한 번은 커밋한다. 메시지는 영어 동사로: `feat: add record form`
- `main`에 바로 커밋한다. 혼자 하는 프로젝트라 브랜치를 나누지 않는다.
- `NOTES.md`에 매일 코드 설명 3~5줄 + 모르겠는 것 한 줄. GitHub에 같이 올린다.
- Claude Code에는 **한 번에 하나씩** 시킨다. 받은 코드는 읽고, 모르는 줄은 설명을 다시 물어본 뒤 넣는다.
- 오류가 나면 먼저 "이 오류가 무슨 뜻인지 설명해줘. 코드는 아직 고치지 마."
- `MONGODB_URI`를 GitHub에 올리지 않는다.

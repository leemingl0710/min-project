# 낚시 조행기 기록 앱 — 요구사항 명세 (1차)

## 1. 개요

- **한 문장 목표**: 낚시 다녀온 날의 조행기(날짜·장소·사진·조과·환경·장비·본문)를 기록하고 나중에 찾아볼 수 있는 웹앱.
- **사용자**: 본인 1인. 비공개 일지.
- **배포 안 함**: 로컬에서 `npm run dev`로만 사용한다. 따라서 로그인·접근 보호는 1차 범위에서 제외한다.
- **한 줄 요약**: 화면은 목록 / 상세 / 작성 / 수정 4개, 기술은 Next.js + TypeScript + Tailwind + Vercel Blob(사진), 데이터는 MongoDB에 저장한다.

## 2. 기술 스택

| 항목 | 선택 |
| --- | --- |
| 프레임워크 | Next.js 14 (App Router, `src/app`) |
| 언어 | TypeScript |
| 스타일 | Tailwind CSS 3 |
| DB | MongoDB (로컬에 직접 설치한 `mongod`, `mongodb` 드라이버) |
| 사진 저장 | Vercel Blob (`@vercel/blob`). 토큰이 없으면 로컬 파일 저장으로 대체 |

### 환경변수 (`.env.local`)

| 이름 | 필수 | 설명 |
| --- | --- | --- |
| `MONGODB_URI` | 필수 | 예: `mongodb://localhost:27017` |
| `MONGODB_DB` | 선택 | DB 이름 (기본값: `fishing-log`) |
| `BLOB_READ_WRITE_TOKEN` | 선택 | 있으면 Vercel Blob에 업로드, 없으면 로컬 파일로 저장 |

## 3. 데이터 모델

조행기 1건 = MongoDB `trips` 컬렉션의 문서 1개.

```ts
type Photo = {
  url: string;       // 표시용 URL (Blob 공개 URL 또는 로컬 경로)
  pathname: string;  // 삭제할 때 쓰는 식별자 (Blob pathname 또는 로컬 파일명)
  isCover: boolean;  // 대표 사진 여부 (한 조행기에 최대 1개)
};

type Trip = {
  _id: ObjectId;
  date: string;        // 출조 날짜 (YYYY-MM-DD)
  place: string;       // 장소
  photos: Photo[];     // 사진 여러 장
  catchNote: string;   // 조과 (자유 텍스트) 예: "도다리 3마리(최대 32cm), 놀래미 1마리"
  conditions: string;  // 환경 (자유 텍스트) 예: "맑음, 수온 21.5도, 6물, 북동풍 3m/s"
  gear: string;        // 장비 (자유 텍스트) 예: "로드 A + 릴 B, PE0.8, 지그헤드 5g"
  body: string;        // 본문 (일반 텍스트, 줄바꿈 유지)
  createdAt: Date;
  updatedAt: Date;
};
```

- 조과·환경·장비는 **표로 구조화하지 않고 자유 텍스트 한 칸씩** 입력한다. (그래서 어종별·월별 통계는 1차 범위가 아니다.)
- 본문은 마크다운이 아닌 **일반 텍스트**이며 줄바꿈만 그대로 보여준다.

## 4. 화면

### 4.1 목록 `/`

- 상단에 **"+ 조행기 작성"** 버튼.
- **키워드 검색**: 장소·본문·조과 등 텍스트 필드에서 키워드를 찾는다(대소문자 구분 없음).
- **정렬**: 출조 날짜 최신순 고정.
- **카드**: 대표 사진(썸네일), 날짜, 장소, 본문 앞부분. 클릭하면 상세로 이동.
- 기록이 하나도 없을 때와 검색 결과가 없을 때 각각 안내 문구를 보여준다.

### 4.2 상세 `/trips/[id]`

- "< 목록" 링크, **수정** 버튼, **삭제** 버튼(확인창 → 삭제 후 목록으로).
- 날짜, 장소.
- **사진 갤러리**: 대표 사진을 먼저, 나머지를 이어서 표시.
- **조과 / 환경 / 장비** 섹션.
- 본문(줄바꿈 유지).
- 없는 `id`로 들어오면 "조행기를 찾을 수 없음" 안내와 목록 링크를 보여준다.

### 4.3 작성 `/trips/new` · 수정 `/trips/[id]/edit`

두 화면은 같은 폼 컴포넌트를 공유한다.

- 입력: 날짜(기본값 오늘), 장소, 조과, 환경, 장비, 본문.
- **사진**: 파일 선택으로 여러 장 업로드, 업로드된 사진 중 **대표 사진 지정**, 사진 개별 제거.
- **저장 버튼**을 눌러야 저장된다. 저장 후 상세 화면으로 이동.

## 5. 서버 API (Next.js Route Handler)

DB와 사진 저장소 접근은 모두 서버에서만 한다.

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/api/trips` | 목록 조회 (검색 키워드 파라미터, 날짜 최신순) |
| POST | `/api/trips` | 새 조행기 저장 |
| GET | `/api/trips/[id]` | 1건 조회 |
| PUT | `/api/trips/[id]` | 수정 |
| DELETE | `/api/trips/[id]` | 삭제 (딸린 사진 파일도 함께 삭제) |
| POST | `/api/upload` | 사진 업로드 → `{ url, pathname }` 반환 |
| DELETE | `/api/upload` | 사진 1장 삭제 (`pathname` 기준) |

## 6. 기능 요구사항

| # | 기능 | 설명 |
| --- | --- | --- |
| F1 | 조행기 작성 | 날짜·장소·조과·환경·장비·본문·사진을 저장 |
| F2 | 목록 조회 | 날짜 최신순으로 카드 목록 |
| F3 | 검색 | 키워드로 조행기 찾기 |
| F4 | 상세 조회 | 사진 갤러리와 모든 항목 보기 |
| F5 | 수정 | 모든 항목과 사진 구성을 고쳐 저장 |
| F6 | 삭제 | 확인 후 삭제, **올린 사진 파일까지 정리** |
| F7 | 사진 여러 장 + 대표 지정 | 업로드·제거·대표 사진 선택 |
| F8 | 영속성 | dev 서버나 브라우저를 다시 켜도 MongoDB에 그대로 남아 있음 |

## 7. 1차 범위에서 제외

- 배포(Vercel 등), 로그인·접근 보호
- 장소별·어종별 필터, 정렬 옵션 전환
- 통계 화면, 지도, 달력 뷰
- 마크다운 본문, 리치 텍스트 에디터
- 이미지 리사이즈·썸네일 생성·EXIF(촬영 위치/시각) 활용
- 자동 테스트

## 8. 완료 기준 (인수 시나리오)

`npm run dev`로 실행해 다음이 모두 되면 1차 완료다.

1. 조행기를 작성한다: 날짜·장소·조과·환경·장비·본문 입력, 사진 여러 장 업로드, 대표 사진 지정 후 저장.
2. 목록에 대표 사진·날짜·장소가 보이고, 조행기가 여러 개일 때 날짜 최신순으로 정렬된다.
3. 키워드 검색으로 해당 조행기를 찾을 수 있다.
4. 상세에서 사진 갤러리(대표 사진 먼저)와 조과·환경·장비·본문이 모두 보인다.
5. 수정 화면에서 내용과 사진 구성을 바꿔 저장하면 상세·목록에 반영된다.
6. 삭제하면 목록에서 사라지고, **그 조행기에 올렸던 사진 파일도 Blob(또는 로컬 저장 위치)에서 삭제된다.**
7. dev 서버와 브라우저를 다시 켜도 데이터가 그대로 남아 있다.
8. `npm run lint`와 `npm run build`가 오류 없이 통과한다.

## 9. 미결 사항 (구현 단계에서 결정)

- 사진 업로드 경로: 클라이언트에서 Blob으로 직접 업로드 vs 서버 라우트 경유
- Blob 토큰이 없을 때 로컬 저장 위치 (예: `public/uploads`)
- 대표 사진을 지정하지 않았을 때 첫 번째 사진을 대표로 쓸지
